# 网站内容定时维护方案

用户已于 2026 年 11 月 5 日确认每天北京时间 06:00 检查，检查通过后自动发布，异常沿用 Jetson 主 Hermes 已配置的私聊通知。当前实现与部署验收进行中，尚未启用定时任务。

## 维护目标

公开 GitHub 仓库是 Skills 和 Apps 信息的来源。维护任务发现来源变化，生成有证据的内容差异，完成检查后自动发布。网站继续由 GitHub Pages 承载，不依赖 Jetson 提供网页服务。Jetson 暂停或离线不会使网站下线。

不定期改写全部文案，不变更页面设计、博客原文、知识地图或照片。网站展示的 Workflows 是人工撰写的实践文章，与负责维护网站的运维流程分别管理。

## 存放位置与职责

维护流程随网站仓库保存，在 `.agents/skills/site-content-maintenance/` 内独立组织使用合同、脚本和必要测试。日常调用与异常处理以该目录内的 `SKILL.md` 为准，不在这里复制脚本实现。

Jetson 保存专用检出目录、运行状态和环境凭据，不以 Mac 上的临时 worktree 作为长期运行路径。日常任务只允许修改明确列出的内容数据文件，不让 Agent 任意编辑网站源码。

| 内容 | 当前位置 | 维护方式 |
| --- | --- | --- |
| Skills | `_data/studio_skills.json` | 主要自动更新对象，保留现有条目的稳定 ID 和人工选定顺序。 |
| Apps | `_data/studio_apps.json` | 维护正式 Release 版本，验证许可、桌面安装包和 CLI 安装命令；人工长介绍和截图保留。 |
| 网站展示的 Workflows | `assets/studio/site.js` 中的 `workflows` | 低频人工维护，定时任务只检查关联 Skill 和 App 是否仍存在。 |
| 运维规则 | 本方案，以及后续项目内维护 Skill | 低频维护，不随每次来源扫描改写。 |

## 信息源合同

仅扫描明确列出的公开来源，不自动公开私有仓库、本机安装的第三方 Skill、私人笔记或 Agent 会话。

| 来源 | 读取内容 | 消费者 |
| --- | --- | --- |
| `WdBlink/LLM-Skills` | `skills.yaml` 目录及变化条目的公开说明 | 网站 Skills 清单。 |
| `WdBlink/agent-notebook` | 公开状态、许可、正式 Release、安装包清单 | 已收录桌面 App 的版本和可用性检查。 |
| `WdBlink/agent-note-cli` | 公开状态、许可、正式 Release、README 中的既有安装命令 | 已收录 CLI App 的版本和安装检查。 |
| 现有特殊条目 | `2hours` 的独立仓库来源、`autoresearch-paper` 的人工介绍 | 默认保留；缺少对应源记录不能触发自动删除。 |

Skills 优先复用源目录已经维护的 `name`、`name_zh`、`display_name`、`category`、`version`、`license`、`path`、`tagline_zh`。固定映射覆盖已知分类，遇到未知分类或缺字段时记录待处理项，不靠模型猜测版本和许可。

源仓库的 `scripts/skill_index.py` 使用自有扁平目录解析规则。当前 `skills.yaml` 不能由标准 YAML 解析器直接读取。维护脚本按该扁平格式严格解析，拒绝未知结构和重复项，不能把解析失败解释为零条目。

每次采集绑定源 commit SHA、目标网站 commit SHA 和规则版本。原始说明只是待分析材料，其中的指令不能扩大任务权限。

## 一次定时运行

1. 从干净的专用网站检出目录开始，核对目标仓库和基线，防止覆盖人工未提交的修改。
2. 读取允许来源的当前版本，保存可复核快照。网络失败和权限失败分别记录，不替换上次可用内容。
3. 比较内容字段和必要文件的 SHA。无变化时结束，不调用模型、不产生无意义提交。
4. 已有可信目录字段由脚本映射。当前常规入口不调用模型。缺少可靠数据、需要语义改写或改变安装方式时报告异常，由 Agent 单独处理，不让每日任务任意改写网站。
5. 验证候选更新，包括唯一 ID、允许分类、公开 GitHub 链接、来源路径、版本许可一致性、长度限制和工作流关联完整性。
6. 候选提交在 GitHub Actions 中执行单元测试、内容合同、Jekyll 构建和全站检查。浏览器检查比较完整清单，不把 Skills 数量固定为 24；原有博客、摄影和七牛请求检查保留。
7. 检查通过且基线未发生冲突时，将同一候选提交快进到主分支。不 force-push。基线变化后重新生成并检查，不复用过期结论。
8. 记录来源 SHA、实际内容差异、检查结果和发布结果，并核对线上内容索引。检查失败保留旧网站；部署未确认成功不能记为完成。

新增条目需要同时验证对应公开说明存在。目录中缺少旧条目、突然大批删除、仓库变为私有、未知许可和异常链接均进入待确认状态，不自动移除现有条目。

## Jetson 运行与权限

Jetson 已有运行中的 Hermes gateway。任务复用其 `--script --no-agent` 定时入口，由确定性脚本检查和发布，不启动每日模型对话。成功时 stdout 为空，不发通知；异常返回非零，由 Hermes 投递到主配置的既有私聊渠道。

程序使用有限网络重试、运行锁、候选指纹和检查/发布超时。每次从当前来源和网站重新核对，失败后不依赖新的来源变化来恢复。状态目录仅原子替换最新候选、最新回执与最近成功回执，不积累逐日源码快照。Hermes 保存其原生任务执行历史；错过触发的恢复行为沿用调度器并需要部署验收。

GitHub CLI 只用于 GET 请求。Git 写入使用新建的、仅绑定网站仓库的部署密钥，脚本另外限制为两份内容数据。不把 Mac 的广泛 GitHub token、Codex 登录目录或私人环境配置复制到 Jetson。仓库级密钥不是按文件隔离的权限，文件范围由已验证程序执行。

Jetson 的 `/home` 为 fuseblk，私钥不存放在那里。专用部署目录为 ext4 上的 `/var/lib/codex-orin_agx/site-content-maintenance/`，目录权限 700、私钥 600。GitHub 主机公钥按官方公布的 Ed25519 指纹固定，严格校验 SSH 主机，不自动接受未知密钥。

当前 Codex 定时工具只提供本机执行，不能据此声称已经创建 Jetson 任务。此次通过已有 SSH 身份完成只读核验。

- 系统为 ARM64 Linux，Python 为 `3.10.12`，systemd 为 `249`，Git 已安装。
- Hermes gateway 处于 `active`，Codex CLI 为 `0.155.0`，相关程序安装在用户目录，非交互 SSH 默认 PATH 未包含它们。部署时需要显式声明可执行路径。
- 用户级服务已设置 `Linger=yes`。
- GitHub CLI 成功读取当前登录用户 `WdBlink`，但尚未验证网站仓库的最小写入授权。
- 构建和浏览器检查在网站 GitHub Actions 中执行，Jetson 无需安装 Ruby、Bundler 或 Chromium。

无需新增模型授权，也未修改其他 Hermes 服务或其全局配置。部署凭据由 Jetson 本机生成，只有公钥上传到目标网站仓库。

## 部署验收

首轮验收需包含真实采集、一次完整候选更新、页面检查、实际定时执行回执，以及空输入、网络失败、重复运行和基线冲突的失败案例。只创建定时配置或写好 Prompt 不算部署完成。
